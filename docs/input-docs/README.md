# input-docs 使用说明

这里是后续增量规划文档入口。

## 给用户

把新的规划、想法、讨论稿或外部文档放在 `docs/input-docs/` 根目录，然后告诉 Codex 读取即可。

## 给 Codex

处理新输入时必须先做文档整合，再开发：

1. 读取根目录的新 `.md` 文件。
2. 判断它是新增规划、旧内容重复、已过期信息，还是只适合归档的想法。
3. 将长期产品变化合并进 `../PRODUCT.md`。
4. 将长期技术变化合并进 `../TECHNICAL.md`。
5. 将完成记录或采纳记录写进 `../CHANGELOG.md`。
6. 开始开发前，审查已处理输入是否需要保留。
7. 已整合、重复、过期或无独立追溯价值的输入直接删除。
8. 只有仍有独立参考价值、需要追溯来源的材料，才移到 `archive/YYYY-MM-DD/` 或更具体的归档目录。

## 归档原则

`archive/` 不是默认留档区。它只保存短期内仍可能被引用的原始材料；一旦内容已经完全沉淀到核心文档，或确认只是旧版本重复内容，就应删除。
