# 趣灵 aha-flash — 产品设计文档 V5

文档定位：基于 V1-V4 迭代经验收束后的产品定义。本文档替代 PRODUCT.md 的产品定位和体验设计部分，技术架构和 CHANGELOG 仍然独立维护。

制定时间：2026-06-11

## 1. 产品定位

**一句话**：给"不想浪费时间但也不想动脑子"的人，提供一个比刷短视频有收获、比学习轻松的知识轻消费体验。

**趣灵不是**：学习工具、维基百科替代品、深度学习平台、考试辅助。

**趣灵是**：知识版的休闲游戏——打开 → 选一个感兴趣的话题 → 闯几个小关 → 感觉"没白过这段时间" → 关掉。

### 差异化定位

| | 抖音/B站 | 多邻国 | 得到/极客时间 | **趣灵** |
|---|---|---|---|---|
| 用户心智 | 纯消遣 | 功利学习 | 功利学习 | **不内疚的消遣** |
| 认知负荷 | 零 | 中 | 高 | **低——"我好像懂了"就够** |
| 单次时长 | 15秒-无限 | 5-15分钟 | 30分钟+ | **3-5分钟一组挑战** |
| 用户事后感觉 | 空虚 | 有成就感 | 有收获 | **"没浪费，还挺有意思"** |
| 进入方式 | 被动刷 | 主动打卡 | 主动学习 | **兴趣驱动，轻量选择** |

### 核心假设（需要验证）

> 存在一群用户——他们想休息，但不满足于短视频的"空虚感"，又没有动力打开得到/多邻国——趣灵提供一个"不内疚的第三种选择"。

**最小验证标准**：用户在没有功利目标的情况下，自愿完成 3 个知识微挑战。

## 2. 目标用户

| 用户类型 | 场景 | 痛点 | 趣灵给什么 |
|----------|------|------|-----------|
| 职场间隙者 | 午休、通勤，不想刷短视频但也不想看长文 | 碎片时间不知道怎么填 | 一个概念 + 3-4 关，5 分钟结束 |
| 轻度好奇心持有者 | "贝叶斯定理到底是啥？"但没有精力看教材 | 好奇心被入门门槛劝退 | 一个互动挑战，通过试错自己总结出来 |
| 睡前学习党 | 睡前想看点有用的但太累学不动 | 学习 = 累，娱乐 = 空虚 | 轻到可以躺着完成的互动 |

**不是目标用户**：考试备考者、学术研究者、需要深度笔记的人。

---

## 3. 核心体验循环

```
打开趣灵 → 看到感兴趣的话题 → 进入微挑战流
→ 第1关：试一下 → ✓/✗ 反馈 → 第2关：再试试
→ 第3关：好像懂了 → ✨ 小成就 → 想看下一个话题
```

**与旧版的根本区别**：
- 旧版：用户**输入**概念 → LLM 生成组件 → 用户**学习**
- 新版：用户**浏览**话题 → 进入预设挑战流 → 用户**闯关**

## 4. 页面架构

趣灵由三个页面组成，无标签栏，无侧栏，无聊天历史。

### 4.1 Explore（入口页）

**用户来到这做什么**：看看有什么好玩的话题，挑一个开始。

**包含**：
- 精选话题卡片（8-12 张），每张 = 概念名 + 一句话引入 + 难度标签 + 预计时长
- 话题分类筛选（科技/经济/哲学/心理/历史/数理）
- 简单的搜索入口（输入概念名，系统匹配最接近的话题）

**不包含**：
- 知识图谱入口（太重）
- 创作者内容流（没有创作者）
- 热门排行/社交推荐（没有社交）

**冷启动策略**：初期用 6-8 个手工精选话题（mock data），每个话题绑定一组 Flow Steps。用户完成一个话题后，Explore 刷新为新的推荐话题。

### 4.2 Flow（核心体验页）

**用户来到这做什么**：全屏沉浸闯关。

**布局**：三段式极简布局
- **顶栏**：退出按钮（×）+ 绿色进度条（当前关/总关数）
- **中央舞台**：当前关卡的单一交互组件，无边框，轻阴影托起
- **底部操作台**：横跨全宽的"检查/继续"大按钮，颜色变化标识状态（灰=待确认、绿=正确、红=错误）

**交互规则**：
- 每关一个组件，用户必须先交互再看到反馈
- 正确 → 绿按钮 + 趣灵精灵撒花 → 点击"继续"滑入下一关
- 错误 → 红按钮 + 简短解释（为什么错）→ 可以重试或跳过
- 最后一关完成 → 展示本话题的小结卡片 + "已掌握 X 个概念，继续探索？"
- 任意时刻可点击 × 退出，进度不保存（轻消费，不需要续关压力）

**知识点驱动 Pattern 匹配**：
系统根据话题的知识类型自动选择最合适的 Pattern：

| 知识类型 | 示例 | 匹配 Pattern |
|----------|------|-------------|
| 概率/不确定性 | 期权、保险、天气预测 | probability, simulation_play |
| 因果/历史 | 工业革命、物种演化 | process_timeline, narrative_branch |
| 对比/选择 | 资本主义vs社会主义 | comparison, classification_sort |
| 系统/网络 | DNS 解析、区块链 | system_builder |
| 术语/概念 | 边际效用、奥卡姆剃刀 | concept_memory, knowledge_check |
| 参数/推演 | 复利计算、供需曲线 | parameter_explore |

**内容来源**：
- 初期：LLM 实时生成 + Eval 体系把关（延续现有架构）
- 中期：用户满意度高的组件标记为"稳定版"存入精选库，减少重复生成成本
- 不采用：用户上传内容、创作者投稿、社区创作

### 4.3 Hub（个人页）

**用户来到这做什么**：快速回忆 + 看看自己闯了多少关。

**包含**：
- 顶部轻量成就：**"已闯过 X 关 | 邂逅了 Y 个概念"**
- 概念卡片墙：每个学过的概念一张小卡片，显示概念名 + 一句话摘要 + 闯过几关
- 点击卡片 → 快速回顾模式（30 秒重温核心机制，不是重新闯关）
- 卡片按最近学习时间排列（最新在前）

**不包含**：
- 知识图谱/思维导图（太重，和轻消费定位冲突）
- 学习笔记/标注/收藏
- 社交分享/排行榜
- 长期学习数据看板

## 5. 内容策略

### 5.1 知识选择原则

趣灵选知识的标准 — 不是"有深度"，是"有顿悟感"：

- ✅ 一句话说不清，但三关互动能让人"啊哈"一下的概念
- ✅ 日常生活中可能碰到，大概知道但说不清楚的东西（贝叶斯、边际效应、复利）
- ✅ 有机制可拆解——可以被映射到 probability/timeline/comparison 等 Pattern
- ❌ 纯记忆性知识（历史年份、化学式）
- ❌ 需要长期练习的技能（编程、外语）
- ❌ 无法在 3-4 关内讲清的大主题

### 5.2 LLM 生成策略

**System Prompt 核心变化**：
- 旧：根据用户输入生成一个交互组件
- 新：根据知识点生成 3-4 步微挑战流，每步匹配最合适的 Pattern

**Flow Steps 结构**（替代旧版的单组件生成）：
```
Step 1：引起好奇（concept_memory / knowledge_check）
  → "你觉得哪个说法是对的？"盲猜选择题
Step 2：建立直观（parameter_explore / simulation_play）
  → "试试拖这个滑块，看看会发生什么"
Step 3：理解机制（narrative_branch / comparison / system_builder）
  → "如果你做了X选择，结果会是？"
Step 4（可选）：回顾巩固（classification_sort / concept_memory）
  → "现在重新排列这些卡片，看看你真的懂了没"
```

**质量保障**：沿用现有 Eval 体系（32 个用例 + 自动回归），扩展到覆盖 Flow Steps 场景。

## 6. 设计原则

以下原则来自 V1-V4 迭代经验收束，作为所有功能决策的基线：

**1. 轻消费第一，学习第二**
每个设计决策先问：这是在帮用户"学懂"，还是在帮用户"不内疚地消磨时间"？如果是前者，砍。

**2. 知识决定交互形式，不让人选**
10 个 Pattern 是题型，匹配权交给系统。用户只需要选话题，不需要理解"probability 和 simulation_play 有什么区别"。

**3. 单屏单任务**
Flow 页永远只有当前这一个交互。没有侧栏、没有导航、没有消息流。用户只需要做一件事：和当前组件互动。

**4. 即时反馈 + 轻量成就**
对/错必须立刻可感知。正确 = 绿色 + 精灵动画 + "继续"。错误 = 红色 + 一句话解释 + 可以重试。完成一组 = 进度数字 +1。不引入惩罚、排行榜、生命值。

**5. 无负担离开**
× 按钮永远可见。退出不挽留、不弹窗、不打折扣。"需要毅力才能坚持"的产品不是趣灵。

**6. 信息架构极度克制**
三个页面，无标签栏，无深层导航。Explore → Flow → Hub 的路径不超过两次点击。

## 7. 技术路线

### 保留（从现有架构继承）

| 资产 | 用途 |
|------|------|
| Generative UI Schema（V2） | Flow Steps 的渲染协议 |
| 10 类交互 Pattern | 微挑战的题型池 |
| Stateful Memory（轻量） | 用户已学概念 + 学习偏好 |
| Eval 体系（32 用例 + 自动回归） | LLM 生成内容的质量把关 |
| Tool Calling + 三重兜底 | 生成稳定性 |
| 趣灵角色提示系统 | Flow 页的情绪反馈 |
| Explore / Studio / Hub 路由基础 | 重命名为新三页面 |

### 变更

| 旧 | 新 | 原因 |
|----|-----|------|
| Studio（创作者工作台） | **搁置**，仅保留底层 Skills 封装 | 创作者端工作量过大，先验证消费端 |
| 用户输入概念 → 生成 | 浏览话题 → 进入预设 Flow | 输入门槛高，兴趣驱动的浏览更轻 |
| /sandbox 知识沙盒 | **删除入口**，数据兼容保留 | 和轻消费定位冲突 |
| 三档深度（rapid/scenario/mapping） | **移除**，统一为浅层体验 | 不追深度 |
| 知识图谱 | **移除** | 太重 |
| Hub 知识图谱视图 | 改为轻量卡片墙 + 成就数字 | 快速回忆 > 知识管理 |

### 新增

| 功能 | 说明 |
|------|------|
| Flow Steps 引擎 | LLM 生成 3-4 步微挑战流替代单组件生成 |
| 知识类型 → Pattern 匹配规则 | System Prompt 中加入自动匹配逻辑 |
| 趣灵精灵 4 态动画 | 思考/闲置/庆祝/遗憾 |
| Explore 话题精选卡片 | 冷启动用 mock 数据，后续接 LLM 动态生成 |
| 轻量成就数字 | Hub 顶部"已闯 X 关，邂逅 Y 个概念" |

## 8. V1 范围

### 8.1 V1 做

- [ ] Explore 页：8 个手工精选话题 + 分类筛选 + 搜索
- [ ] Flow 页：三段式布局 + 进度条 + 底部变色操作栏 + 组件切换动画（framer-motion）
- [ ] Flow Steps 引擎：LLM 生成 3-4 步微挑战流，知识类型自动匹配 Pattern
- [ ] 趣灵精灵：4 态情绪动画
- [ ] Hub 页：轻量成就数字 + 概念卡片墙 + 快速回顾
- [ ] Eval 体系扩展到 Flow Steps 场景
- [ ] 公开部署（V1 默认体验额度）

### 8.2 V1 不做

- 用户注册/登录
- 付费/订阅
- 创作者工作台（Studio）
- Skills 发布（远期，底层架构保留）
- 社交功能
- 离线模式
- 内容审核后台

## 9. 成功指标（V1）

| 指标 | 目标 | 验证方式 |
|------|------|---------|
| 话题进入率 | Explore → Flow > 60% | 埋点 |
| Flow 完成率 | 进入 Flow 后通关率 > 50% | 埋点 |
| 连续话题消费 | 完成1个话题后进入下个 > 30% | 埋点 |
| 次日留存 | > 15%（教育类产品基准 ~1.4%，多邻国 ~10%） | 埋点 |
| 组件生成成功率 | JSON 合法 + 路由准确 > 95% | Eval 自动回归 |
