# 趣灵 aha-flash — 产品与路线

> 文档定位：记录当前产品真相、体验原则、互动组件质量标准和 V1 路线。临时输入文档放入 `docs/input-docs/`，完成整合后归档或删除。

> 当前版本：V5。V5 将趣灵从“AI 生成互动组件工具”收束为“知识版休闲游戏 / 不内疚的知识消遣”。
## 1. 产品定位

**一句话**：给"不想浪费时间但也不想动脑子"的人，提供一个比刷短视频有收获、比学习轻松的知识轻消费体验。

**趣灵不是**：学习工具、维基百科替代品、深度学习平台、考试辅助。

**趣灵是**：知识版的休闲游戏——打开 → 选一个感兴趣的话题 → 闯几个小关 → 感觉"没白过这段时间" → 关掉。

### 差异化定位

| | 抖音/B站 | 多邻国 | 得到/极客时间 | **趣灵** |
|---|---|---|---|---|
| 用户心智 | 纯消遣 | 功利学习 | 功利学习 | **不内疚的消遣** |
| 认知负荷 | 零 | 中 | 高 | **低——"我好像懂了"就够** |
| 单次时长 | 15秒-无限 | 5-15分钟 | 30分钟+ | **3-5分钟一组挑战** |
| 用户事后感觉 | 空虚 | 有成就感 | 有收获 | **"没浪费，还挺有意思"** |
| 进入方式 | 被动刷 | 主动打卡 | 主动学习 | **兴趣驱动，轻量选择** |

### 核心假设（需要验证）

> 存在一群用户——他们想休息，但不满足于短视频的"空虚感"，又没有动力打开得到/多邻国——趣灵提供一个"不内疚的第三种选择"。

**最小验证标准**：用户在没有功利目标的情况下，自愿完成 3 个知识微挑战。

## 2. 目标用户

| 用户类型 | 场景 | 痛点 | 趣灵给什么 |
|----------|------|------|-----------|
| 职场间隙者 | 午休、通勤，不想刷短视频但也不想看长文 | 碎片时间不知道怎么填 | 一个概念 + 3-4 关，5 分钟结束 |
| 轻度好奇心持有者 | "贝叶斯定理到底是啥？"但没有精力看教材 | 好奇心被入门门槛劝退 | 一个互动挑战，通过试错自己总结出来 |
| 睡前学习党 | 睡前想看点有用的但太累学不动 | 学习 = 累，娱乐 = 空虚 | 轻到可以躺着完成的互动 |

**不是目标用户**：考试备考者、学术研究者、需要深度笔记的人。

---

## 3. 核心体验循环

```
打开趣灵 → 看到感兴趣的话题 → 进入微挑战流
→ 第1关：试一下 → ✓/✗ 反馈 → 第2关：再试试
→ 第3关：好像懂了 → ✨ 小成就 → 想看下一个话题
```

**与旧版的根本区别**：
- 旧版：用户**输入**概念 → LLM 生成单个组件 → 用户**学习**
- 新版：用户**输入或选择**起点 → AI 生成三关 Flow → 用户**闯关并继续探索分支**

## 4. 页面架构

趣灵由三个页面组成，无标签栏，无侧栏，无聊天历史。

### 4.1 Explore（入口页）

**用户来到这做什么**：输入一个想理解的知识点，或从示例起点里挑一个开始。

**公开入口包含**：
- 自由输入框：用户输入任意 topic 后，默认由 AI 推荐 Pattern 并生成三关 Flow。
- AI 自动选型：系统根据 KnowledgeBlueprint 自动选择三关的 Pattern；仅当生成失败时，用户可以选择另一种知识拆解方式重试。
- 5 个精选 topic 卡片：`bayes-starter`、`dns-router`、`options-risk`、`industrial-revolution`、`inflation-deflation`，作为低风险示例起点，并覆盖全部 10 类 Pattern。
- Hub 入口：用户走完任一 Flow 后能看到本机完成记录。

**暂不展示**：
- 8-12 张完整话题流、分类筛选和搜索（会让公开作品像未完成产品）。
- 知识图谱入口（太重）。
- 创作者内容流、热门排行、社交推荐（不是求职作品的重点）。

**冷启动策略**：默认展示自由生成入口，五条完整垂直切片作为兜底示例；当用户有明确兴趣时，优先让用户直接生成自己的知识路径。

### 4.2 Flow（核心体验页）

**用户来到这做什么**：全屏沉浸闯关。

**布局**：三段式极简布局
- **顶栏**：退出按钮（×）+ 绿色进度条（当前关/总关数）
- **中央舞台**：当前关卡的单一交互组件，无边框，轻阴影托起
- **底部操作台**：横跨全宽的"检查/继续"大按钮，颜色变化标识状态（灰=待确认、绿=正确、红=错误）

**交互规则**：
- 每关一个组件，用户必须先交互再看到反馈
- 正确 → 绿按钮 + 趣灵精灵撒花 → 点击"继续"滑入下一关
- 错误 → 红按钮 + 简短解释（为什么错）→ 可以重试或跳过
- 最后一关完成 → 展示本话题的小结卡片 + "已掌握 X 个概念，继续探索？"
- 任意时刻可点击 × 退出，进度不保存（轻消费，不需要续关压力）

**知识点驱动 Pattern 匹配**：
系统根据话题的知识类型自动选择最合适的 Pattern：

| 知识类型 | 示例 | 匹配 Pattern |
|----------|------|-------------|
| 概率/不确定性 | 期权、保险、天气预测 | probability, simulation_play |
| 因果/历史 | 工业革命、物种演化 | process_timeline, narrative_branch |
| 对比/选择 | 资本主义vs社会主义 | comparison, classification_sort |
| 系统/网络 | DNS 解析、区块链 | system_builder |
| 术语/概念 | 边际效用、奥卡姆剃刀 | concept_memory, knowledge_check |
| 参数/推演 | 复利计算、供需曲线 | parameter_explore |

**内容来源**：
- 初期：LLM 实时生成 + Eval 体系把关（延续现有架构）
- 中期：用户满意度高的组件标记为"稳定版"存入精选库，减少重复生成成本
- 不采用：用户上传内容、创作者投稿、社区创作

### 4.3 Hub（个人页）

**用户来到这做什么**：快速回忆 + 看看自己闯了多少关。

**包含**：
- 顶部轻量成就：**"已闯过 X 关 | 邂逅了 Y 个概念"**
- 知识路径足迹：按用户走过的节点展示话题、摘要、关键概念和完成时间
- 点击卡片 → 快速回顾模式（30 秒重温核心机制，不是重新闯关）
- 卡片按最近学习时间排列（最新在前）

**不包含**：
- 知识图谱/思维导图（太重，和轻消费定位冲突）
- 学习笔记/标注/收藏
- 社交分享/排行榜
- 长期学习数据看板

## 5. 内容策略

### 5.1 知识选择原则

趣灵选知识的标准 — 不是"有深度"，是"有顿悟感"：

- ✅ 一句话说不清，但三关互动能让人"啊哈"一下的概念
- ✅ 日常生活中可能碰到，大概知道但说不清楚的东西（贝叶斯、边际效应、复利）
- ✅ 有机制可拆解——可以被映射到 probability/timeline/comparison 等 Pattern
- ❌ 纯记忆性知识（历史年份、化学式）
- ❌ 需要长期练习的技能（编程、外语）
- ❌ 无法在 3-4 关内讲清的大主题

### 5.2 LLM 生成策略

**System Prompt 核心变化**：
- 旧：根据用户输入生成一个交互组件
- 新：根据知识点生成 3-4 步微挑战流，每步匹配最合适的 Pattern

**Flow Steps 结构**（替代旧版的单组件生成）：
```
Step 1：引起好奇（concept_memory / knowledge_check）
  → "你觉得哪个说法是对的？"盲猜选择题
Step 2：建立直观（parameter_explore / simulation_play）
  → "试试拖这个滑块，看看会发生什么"
Step 3：理解机制（narrative_branch / comparison / system_builder）
  → "如果你做了X选择，结果会是？"
Step 4（可选）：回顾巩固（classification_sort / concept_memory）
  → "现在重新排列这些卡片，看看你真的懂了没"
```

**质量保障**：沿用现有 Eval 体系（32 个用例 + 自动回归），并新增 Flow Steps 自动化 Eval。当前五个公开切片共同覆盖全部 10 类 Pattern：贝叶斯覆盖小测/卡片/参数，DNS 覆盖系统搭建/分类，期权覆盖概率/模拟/分支，工业革命覆盖时间线，通胀通缩覆盖对比。`eval:flow-manual` 继续用于 10 次人工采样，`eval:flow` 用于自动检查 3 类知识类型 × 每类 5 个固定检查点，覆盖步骤数量、Pattern 链、payload 完整度、文案安全和概念锚点。

## 6. 设计原则

### 6.x 活泼奶油视觉规范（来自 `docs/input-docs/input.md`）

V5 首页与 Hub 采用白底、低饱和产品色和大圆角卡片。颜色不再只追求“鲜艳”，而是按语义角色固定使用，避免 CTA、卡片主题和导航互相抢占注意力。

配色角色：
1. 主蓝 `#4A6FA5`：只用于品牌图标和全局品牌锚点，不参与卡片主题竞争。
2. 行动橙 `#C2703A`：用于主 CTA，例如“开始闯关”；同时作为历史类卡片主题色。
3. 完成绿 `#3D8B6E`：用于“查看完成记录”、完成/记录/图鉴点亮；同时作为经济类卡片主题色。
4. 辅助紫 `#6B5D8A`：用于数理/贝叶斯类卡片主题色。
5. 中性灰 `#7C7C7C`：用于导航、证明条、辅助标签和弱说明文案。

视觉原则：
- 页面底色保持白色，卡片用低饱和奶油色块区分主题。
- 三张首页卡片必须各有一个稳定主题色，但主题色只服务于识别，不抢主 CTA。
- CTA 使用实底色和白字，避免黑灰按钮让页面变成工具感。
- 导航栏和“5 个话题 / 每话题 3 关 / 覆盖 10 类 Pattern”证明条保持中性灰。
- 标题优先保证清晰阅读；卡片标题可以使用对应主题色，页面级大标题不参与多色竞争。
- “只能一行”是文案长度约束，不是视觉截断策略；禁止依赖 `text-overflow: ellipsis` 隐藏超长文案。
- 首页 Hero 副标题控制在 18 个汉字左右；话题卡 hook 控制在 14 个汉字左右；Hub 卡片摘要控制在 16 个汉字左右。
- 首页话题不是平等选项，而是纵向学习路径；首个话题承担默认起点，其余话题按顺序向下展开。
- 顶栏必须反映基础产品结构，至少包含“首页”和“我的图鉴”，当前页需要有明确高亮。
- 卡片区使用“选择一个话题开始”作为行动标题，替代自证式证明条。

## 8. 互动组件质量标准

组件目标不是“暗色卡片里放文字”，而是让用户看见概念机制。

视觉标准：

- 每个 Pattern 有独立主色，而不是全局绿色一把梭。
- 全局使用清爽亮色底，组件主体以白色/浅灰面板承载内容。
- 表面色、容器色、抬高色必须能被肉眼区分，不使用大面积渐变和高饱和边框堆叠。
- 标题、副标题、正文、辅助文字、关键数值有固定层级。
- 卡片、按钮、标签、进度条使用统一圆角规则。
- 间距遵循 8/16/20/24px 的清晰节奏。
- 角色提示使用轻量气泡，不遮挡组件，不替代组件反馈。

Pattern 主色：

| Pattern | 主色 | 语义 |
|---|---|---|
| `probability` | `#F7C948` | 稀有/价值 |
| `parameter_explore` | `#36D399` | 可调节 |
| `concept_memory` | `#78A6FF` | 记忆/认知 |
| `process_timeline` | `#B392F0` | 时间流动 |
| `comparison` | `#F4A261` | 对比/差异 |
| `knowledge_check` | `#FF6B6B` | 正确/错误 |
| `system_builder` | `#35E69B` | 连接/构建 |
|
arrative_branch` | `#E879BA` | 选择/分支 |
| `classification_sort` | `#4DD9C1` | 分类/归位 |
| `simulation_play` | `#FACC15` | 模拟/推演 |

字体层级：

| 层级 | 规格 | 用途 |
|---|---|---|
| 标题 | `text-2xl font-semibold` | 概念名 |
| 副标题 | `text-base font-medium` | 步骤/阶段名 |
| 正文 | `text-sm leading-relaxed` | 解释文本 |
| 辅助 | `text-xs text-[var(--muted)]` | 标签/提示 |
| 数值 | `text-3xl font-bold` | 关键数字 |

禁用：

- `text-lg` 作为标题。
- `text-xl` 作为正文。
- `gap-3` / `gap-7` 等非 4 的倍数间距。
- `rounded-[8px]` 硬编码。
- 组件文件中直接硬编码 Pattern 色值。

间距与圆角：

| 类型 | 规格 |
|---|---|
| 组件内边距 | `p-5` |
| 卡片间距 | `gap-4` |
| 区块间距 | `gap-6` |
| 行内间距 | `gap-2` |
| 卡片/面板 | `rounded-xl` |
| 按钮 | `rounded-lg` |
| 标签/badge | `rounded-md` |
| 进度条 | `rounded-full` |

交互标准：

- 每个组件覆盖 entering、idle、interacting、result、empty、error 六态。
- 主 CTA 有明确可点击反馈。
- 主 CTA 文案必须是具体动作词，让用户知道自己要做什么。
- 关键数字、结果揭示、成功/失败状态必须有语义化动效。
- 完成一次组件交互后给轻量正反馈，默认形式为“理解进度 +1”。
- 所有可点击元素最小高度 44px。
- 深度切换不在顶部提前让用户选三档；默认先给“看一眼”，完成交互后在组件下方/输入框上方用内联引导进入下一档。

状态与微交互参数：

| 状态/交互 | 视觉表现 |
|---|---|
| entering | 250ms fade-in + translateY(16px) 到 0 |
| idle | 主 CTA 使用 `ui-breathe`，opacity 0.9 到 1，周期 2s |
| interacting | 按钮 disabled + spinner，操作区高亮边框 |
| result | 反馈区 `ui-result`，关键数字 `animate-value-pop` |
| empty | `EmptyState` 从中心渐入 |
| error | 组件级 ErrorBoundary |
| 按钮按下 | scale(0.96) 到 1，150ms ease-out |
| 卡片选中 | border-color 变化 + scale(1.02)，200ms |
| 数值变化 | scale(1.3) 到 1，300ms spring |
| 结果揭示 | opacity 0 到 1 + translateY(8px) 到 0，400ms ease-out |
| 成功 | `animate-success-flash`，400ms |
| 失败 | `animate-error-shake`，300ms |

可及性：

- 所有按钮必须 `cursor-pointer`。
- 图标按钮必须有可理解的 `title` 或 `aria-label`。
- 滑块必须有 `aria-label`。
- 深色背景上的文字对比度目标不低于 4.5:1。
- 亮色背景上的正文、按钮和提示文字对比度目标不低于 4.5:1。

内容标准：

- `title` 必须短而具体。
- `description` / `quote` 要包含具体场景。
- `insight` 至少包含一个因果链。
- `explanation` 要说明错在哪里和正确是什么。
- 数组字段至少 3 项。
- Prompt 的正例反例必须同时约束结构和内容，不只约束 JSON 类型。

### 深度渐进

三档深度使用渐进式引导：

| 档位 | 用户动作词 | 系统行为 |
|---|---|---|
| `rapid` | 看一眼 | 默认，一个交互先看懂概念是什么 |
| `scenario` | 试一下 | 完成后引导代入真实场景做决策 |
| `mapping` | 拆开看 | 场景完成后引导拆开原理映射 |

规则：

- 不在输入前展示三按钮。
- 只提示下一档，不回头提示上一档。
- 引导文案是内联文字，不是并排按钮组。
- 点击引导后走完整 API 重新生成该深度 Schema。

## 9. 隐喻生成语言

全局规则：通用语打底，领域语翻译。

- 先用平实中文说清概念动作。
- 再用用户熟悉领域的真实机制、道具、动作或规则做对应。
- 选定术语体系后全文统一，禁止混用。
- 每个抽象概念必须有具体对应物，禁止“像玩游戏一样”这种泛类比。
- LLM 不拿固定术语表硬套，而按“拆动作 -> 找机制 -> 验映射 -> 统一术语 -> 给对应物”推理。
- 推理结果写入 payload 的 `metaphor_trace` 字段，前端不渲染，仅用于调试、评估和回归。

隐喻推理流程：

1. 拆解概念的核心动作：这个概念在做什么，用 1-2 个动词概括。
2. 在用户领域找行为最接近的机制。
3. 逐一验证映射是否成立，选成立度最高的。
4. 选定一个术语体系后全文统一，禁止混用。
5. 每个抽象概念必须有具体对应物，禁止泛类比。

## 11. 成功指标（V1）

| 指标 | 目标 | 验证方式 |

### V5 统一视觉方向：玩具感学习路径 + 个人图鉴册

后续 Explore 与 Hub 必须保持同一套产品气质：趣灵不是后台，不是资料库，而是可以被点亮的知识路径。

- Explore 是“选择路径”：话题以纵向学习路径呈现，第一张卡承担默认起点，其余话题顺序向下展开。
- Hub 是“图鉴册”：不做数据看板，改为图鉴封面、路径节点和 30 秒回看卡片。
- 顶栏结构统一：品牌区 + 首页 + 我的图鉴；当前页必须高亮。
- 卡片语言统一：白底页面、低饱和主题色块、大圆角、粗标题、胶囊标签、厚实 CTA。
- 动效集中在关键瞬间：卡片入场、卡片 hover、完成后点亮图鉴，不做零散装饰动画。
- 文案保持短促直接，单行限制通过文案长度解决，不依赖省略号隐藏。
### V5 连续知识穿行循环

趣灵的核心循环从“首页选话题 -> 三关 -> 回首页”调整为“首页选起点 -> 三关 -> 选择下一步分支 -> 继续三关”。完成一个 Flow 不是终点，而是知识空间里的一个节点。

- Explore 只负责选择起点和切换领域，不再承担每次完成后的默认回流。
- Flow 完成态必须展示 2-3 个 follow-up topic，用户可以直接点选继续探索。
- Follow-up topic 分为 `curated` 精选路径和 `ai_seed` AI 延伸方向；V1 先用静态 mock 跑通连续穿行，后续接入 LLM 生成。
- Hub 记录的是“走过的路径”，不是内容卡片仓库；它应呈现旅程足迹和节点回看。
- 只有用户想换领域或重新选择起点时，才回 Explore。

### Hub 路径卡片颜色规则

Hub 的路径节点不按列表顺序轮换颜色，而是复用 V5 既有四个语义角色色：技术/系统使用主蓝，数理/概率使用辅助紫，历史/时间线使用行动橙，经济/金融使用完成绿。无法归类时默认使用主蓝，避免引入新的 Hub 专属配色体系。

## Dynamic Free Generation Current Contract

- The visible promise is user topic -> ConceptPlan -> three-step Flow -> follow-up branch, not a finite list of prewritten topics.
- ConceptPlan makes free generation auditable: every generated Flow must first decide what the concept really is, what terms anchor it, and which patterns should or should not be used.
- This is the key difference from static authored content: adding or entering a new topic should not require prebuilt content, but it must pass grounding and pattern-fit checks before it is shown as LLM output.
- Manual local checks now pass for Agent and linear programming with source=llm and topic-specific pattern chains.
